# Интеграции: AI и ОРД (план этапа 1)

## 1. AI-провайдеры

Архитектура: интерфейс `AiProvider` с методами `chat()`, `testConnection()`,
`estimateCost()`; адаптеры:
- `openai-compatible` — базовый (OpenAI, DeepSeek, OpenRouter, локальные vLLM/Ollama);
- профили-пресеты с собственными особенностями: DeepSeek (base URL
  `https://api.deepseek.com/v1`, модели задаются владельцем — список меняется),
  при необходимости — другие.

Различия, которые обрабатываем явно: поддержка `response_format`/JSON-режима,
tool calling, reasoning-модели (отдельные поля ответа, иные параметры температуры),
коды ошибок 401/402/429/5xx, тайм-ауты.

Правила:
- AI выключен до настройки; статусы: не настроен → проверка → готов / ошибка.
- Ключ вводится в Mini App, хранится зашифрованным (AES-256-GCM, мастер-ключ в env),
  в браузер не возвращается (только маска `sk-…abcd`), в логи не пишется.
- Лимиты: макс. токенов на запрос, запросов в сутки, бюджет в месяц (оценка по
  тарифу, который вводит владелец), тайм-аут 60 с, ≤ 2 повтора только на 429/5xx.
- Аналитика для AI: приложение само считает агрегаты и передаёт их в виде таблицы
  с периодом и источниками; модель обязана разделять «факты» и «предположения»
  (структурированный ответ), результат валидируется схемой.
- AI создаёт только черновики. Публикация/изменение рекламы — только по кнопке
  владельца.
- Защита от prompt injection: пользовательский контент передаётся как данные в
  разделителях, у модели нет инструментов с внешними действиями.
- Telegram API Terms п. 1.5 запрещает использовать данные Telegram для обучения
  моделей. Мы используем модели только для генерации ответа; в документации
  покупателю укажем выбирать провайдера/тариф без обучения на данных запросов.

Внешние условия: аккаунт у провайдера, оплата им, доступность провайдера из страны
сервера (для российских VPS часть провайдеров может быть недоступна — проверяется
тестом подключения).

## 2. ОРД и ERID

### Что подтверждено (источник — обзор workspace.ru, 2026)
- В ОРД передаются: договоры, акты (с разаллокацией по креативам и площадкам),
  креативы (каждый получает ERID), **статистика показов за месяц** (прирост),
  сведения об участниках (ИНН, форма, ставка НДС, ссылки на площадку).
- Срок — 30 календарных дней после окончания месяца размещения.
- Сбор 3% с дохода от рекламы платят в том числе каналы/блогеры-физлица; расчёт
  делает РКН по данным ОРД, ежеквартально.
- VK ОРД: с 27.04.2026 — обязательная верификация, с мая 2026 — платный, с 19.08.2026
  — поле адреса для физлиц/ИП и новые типы актов.
- У основных ОРД (Яндекс, VK, Ozon, Медиаскаут, ОРД-А, SberAds, Первый ОРД)
  исторически есть API, но доступ — по договору, после идентификации, тарифы
  платные (данные обзора ppc.world 2023 — устарели, нужна сверка).

### Регуляторный риск (подтверждено новостями ФАС, март–июнь 2026)
ФАС заявила, что реклама на ресурсах с ограниченным доступом запрещена (ч. 10.7
ст. 5 ФЗ «О рекламе»), и отнесла к ним Telegram; для Telegram и YouTube объявлен
переходный период без ответственности **до конца 2026 года**. Что будет с 2027 года,
не определено. Это прямо влияет на ценность рекламного кабинета для покупателей из
РФ — см. RISKS.md.

### План
1. MVP — **честный ручной процесс**: поля ERID, договор, акт, реквизиты
   рекламодателя, статус «маркировка: не требуется / ожидает ERID / ERID получен /
   статистика передана», напоминание до 30-го числа, подстановка «Реклама. ИНН/
   наименование. erid: …» в пост, блок предупреждения при публикации без ERID.
2. Интерфейс `OrdAdapter` (registerCreative, submitStats, getStatus) без реализаций.
3. Реальный адаптер (кандидат — VK ОРД) — только когда у владельца есть договор и
   тестовые учётные данные. Без них интеграцию не делаю и не имитирую.

Продукт не будет заявлять о юридическом соответствии; в документации покупателю —
рекомендация консультироваться с юристом.
