# Модель безопасности (черновик этапа 1)

## Активы

Bot token, AI-ключи, ключи ОРД, (опционально) MTProto-сессия владельца, данные
рекламодателей (контакты, реквизиты), финансовые данные заказов, черновики,
медиафайлы, токены сессий, токены публичных отчётов.

## Нарушители

1. Внешний аноним в интернете (API, редиректор, публичные отчёты, webhook).
2. Пользователь Telegram, не являющийся владельцем, открывший Mini App/бота.
3. Получатель публичного отчёта, пытающийся увидеть больше.
4. Вредоносный контент (текст поста, рекламный материал) против AI.
5. Компрометация хоста — вне зоны защиты приложения; минимизируем ущерб.

## Меры

| Угроза                                  | Мера                                                                                                                                                      |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Подделка initData (реализовано, этап 3) | HMAC-SHA256: secret = HMAC("WebAppData", bot_token), сравнение в постоянное время; `auth_date` ≤ 1 ч; `initDataUnsafe` на клиенте только для отображения  |
| Чужой пользователь Telegram             | вход только для `OWNER_TELEGRAM_ID`; бот отвечает посторонним нейтрально                                                                                  |
| Кража сессии                            | непрозрачный токен 256 бит, хранится SHA-256, TTL 12 ч, отзыв при выходе, ограничение числа сессий                                                        |
| Поддельный webhook                      | `secret_token` при setWebhook + проверка заголовка; путь не угадываемый                                                                                   |
| IDOR / доступ к чужим сущностям         | проверка `ownerId` в сервисном слое на каждый запрос, тесты на прямой вызов API                                                                           |
| SQL injection                           | Drizzle (параметризация), сырой SQL — только через шаблон `sql\`…\``                                                                                      |
| XSS                                     | React-экранирование, без `dangerouslySetInnerHTML`; рендер предпросмотра из entities; CSP                                                                 |
| SSRF                                    | AI base URL и целевые URL трекинга: только https, запрет приватных/loopback/link-local адресов после DNS-разрешения, без следования редиректам на сервере |
| Открытый редирект                       | редиректор ведёт только на URL, сохранённый в БД для этого slug; slug ≥ 128 бит                                                                           |
| Перебор отчётов                         | токены ≥ 128 бит, хэш в БД, отзыв, rate limit, одинаковый 404 для несуществующих и отозванных                                                             |
| Накрутка кликов                         | rate limit по хэшу IP, отсечение известных ботов по UA (в т.ч. превью-краулер Telegram), флаг `isSuspect`, без сырых IP                                   |
| Повтор критических операций             | идемпотентные ключи публикаций, блокировки строк, уникальные индексы                                                                                      |
| Утечка секретов в логи                  | pino redact-пути, сериализаторы ошибок без заголовков Authorization, тест на отсутствие секретов в логах                                                  |
| Секреты в БД                            | AES-256-GCM, мастер-ключ `APP_ENCRYPTION_KEY` только в env/файле с правами 600; ротация по процедуре                                                      |
| Prompt injection                        | контент как данные, нет инструментов с внешними действиями, подтверждение владельцем                                                                      |
| Загрузки                                | лимиты размера, проверка сигнатуры файла (magic bytes), случайные имена, раздача без исполнения                                                           |
| Сеть                                    | наружу только 80/443 (Caddy); Postgres/Redis — внутренняя сеть; UFW по инструкции                                                                         |
| Заголовки                               | HSTS, CSP (`frame-ancestors` для web.telegram.org), nosniff, Referrer-Policy; CORS только свой домен                                                      |
| Зависимости                             | `pnpm audit` в CI, зафиксированные версии, Renovate по желанию                                                                                            |
| Production-ошибки                       | без стектрейсов наружу, корреляционный id в ответе                                                                                                        |

Продукт не объявляется «полностью безопасным»; итоговый аудит — этап 8.
