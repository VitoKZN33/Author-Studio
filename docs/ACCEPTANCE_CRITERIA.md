# Критерии приёмки этапов

Статусы функций: не начата · в разработке · реализована, не проверена · проверена
автоматически · проверена интеграционно · проверена в целевом окружении ·
заблокирована внешними условиями.

**Этап 2 — фундамент**
- `pnpm typecheck`, `pnpm lint`, `pnpm test` проходят; сборка web и server.
- `docker compose config` валиден; `docker compose up` поднимает все сервисы,
  readiness = 200 при живых БД и Redis и 503 при недоступной БД.
- Миграция применяется на пустую БД; повторный запуск — без изменений.
- Тестовое задание BullMQ переживает перезапуск worker.
- Приложение не стартует при отсутствии обязательных env (понятная ошибка на русском).
- В логах нет значений из списка секретов (автотест).

**Этап 3 — Telegram и авторизация**
- Подделанный/просроченный/чужой initData → 401 (автотесты).
- Webhook без секрета → 401; обновления обрабатываются через очередь.
- Подключение канала показывает каждое право и инструкцию, если чего-то нет;
  удаление бота из канала меняет статус и отправляет уведомление.
- Проверено на реальном боте и тестовом канале (после выдачи токена).

**Этап 4 — публикации**
- Валидация лимитов Telegram до отправки (unit-тесты по каждому лимиту).
- Автосохранение, конфликт версий → предложение выбора, восстановление после закрытия.
- Отложенная публикация срабатывает после перезапуска всех контейнеров.
- Двойной запуск задания не создаёт два поста (интеграционный тест).
- Многоканальная публикация показывает результат по каждому каналу.
- `AMBIGUOUS` не повторяется автоматически.

**Этап 5 — аналитика**
- Для каждой метрики в UI указан источник и период; «нет данных» ≠ 0.
- Расчёты (Δ, базовая линия, лучшее время) покрыты unit-тестами на фиксированных данных.

**Этап 6 — реклама**
- Статус оплаты и статус публикации независимы.
- Закреп/открепление/удаление переживают перезапуск и не дублируются.
- Публичный отчёт не содержит контактов, комментариев, цены (тест на ответ API);
  отозванный токен → 404.
- Трекинг: нельзя перенаправить на произвольный URL; боты-превью не считаются кликами.

**Этап 7 — AI**
- Ключ не попадает в ответы API и логи (тест).
- Обработаны 401/429/5xx/тайм-аут/невалидный JSON (тесты с моками).
- Аналитический ответ содержит раздел фактов, период и оценку достаточности данных.

**Этап 8 — готовность к продаже**
- Установка на чистый поддерживаемый Ubuntu LTS по документации — проверена.
- Бэкап → восстановление на отдельной среде — проверено.
- Обновление с предыдущей версии без потери данных — проверено.
- Таблица функций со статусами — актуальна.
